# Cangjie-TPC开源软件贡献指导

## 目的

Cangjie-TPC三方开源软件大多是适配的第三开源软件，第三方开源软件数量多，而社区开发人员同样数量多、分布广，为确保 Cangjie-TPC 开源软件的整体质量，特别拟定本指南，供社区贡献者参考。

## 适配软件选入的基本要求

为便于Cangjie-TPC开源软件的维护与演进，在选择适配第三方开源软件时请参考如下原则：

1. 软件必须有明确的来源，Cangjie-TPC 适配的软件必须有清晰定义的上游社区。
2. 必须有明确的适配理由，若需要适配的软件在 Cangjie、Cangjie-TPC 中已存在，则无需适配，避免多版本共存增加维护的复杂性。
3. 适配的软件应该可以基于仓颉编程语言被正确构建，若该软件的运行或者构建依赖一个不能适配的组件，则不能适配该软件。
4. **适配的软件包含不托管源码(对上游开源软件不做任何修改)、托管源码(对上游开源软件进行语言改写，功能适配等侵入式修改)：**
   - 针对不托管源码但需要贡献demo代码体现该软件能力的，demo代码必须以源码方式呈现，其文件夹统一命名为`软件名称_demo`
   - 针对需要托管源码的软件，必须将其放置到单独的代码仓，若该软件引用多个开源软件部分能力，需要在README.OpenSource文件中补充对应软件的开源信息。
5. 适配的软件应当完整保留上游软件的许可证及Copyright信息，不要修改第三方开源软件的原始许可证与Copyright信息。
6. 不建议适配未发布正式版本（如只发布Beta版本）的开源软件。
7. 不能适配有高危漏洞且无解决方案的版本。
8. **针对需修改上游开源软件的三方库，请确保满足该开源软件的许可证要求，修改的文件应当保持其原始许可证条款，新增的文件也建议采用相同的许可证条款。**
9. 适配的开源软件必须在其根目录提供README.OpenSource文件，在该文件中准确描述上游软件名、许可证、许可文件位置、版本、对应版本的上游社区地址、软件的维护Owner、功能描述以及引入的原因。
10. **适配的开源软件存在依赖其他开源软件时，不允许将被动依赖软件嵌套在引入的新的开源软件子目录中，必须剥离所有依赖软件项，原因是嵌套放置依赖软件可能导致多同一款软件多版本、旧版本安全漏洞无法及时修复、开源义务履行合规的风险问题。优先通过 `cjpm` 依赖**

## 适配软件选型检查

| 检查项         | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| 归一化         | 1、检查该软件在Cangjie、Cangjie-TPC中是否已存在，原则上Cangjie、Cangjie-TPC中存在的软件不在做适配。 |
| 来源可靠       | 1、应该从开源软件官网获取或官网指定的代码托管地址获取        |
| 社区活跃       | 1、软件来自知名社区或组织，社区或组织通过发布公告、修改软件仓库状态、将仓库放到特定目录下等方式告知停止维护的，不建议去适配。<br/>2、软件来自个人、小型社区或组织，两年内未发布版本（含正式版本与测试版本），无明确版本计划，社区提交了有效的Bug或PR，但是半年以上未响应的，不建议选用。社区较流行，使用量大(社区fork数或star数在10k以上)的除外。<br/>3、社区运营状态不明确，通过Issue 或者邮件等方式询问社区是否继续维护，半年以上未响应或者答复停止维护的，不建议选用。 |
| 安全漏洞       | 1、检索业界已知公开的安全漏洞，如有高危漏洞需要有应对方案。  |
| 规范化软件名称 | 1、不允许以软件的子模块作为软件名。 |
| 官网信息       | 1、在申请适配请求中准确描述该软件官方网址，如无正式官网则提供主流代码托管商上面对应的项目网址，不能使用maven、mvnrepository、springsource等托管库地址。<br/>2、必须同时提供要适配软件版本的官方源代码包下载地址，以达到可溯源，如需要二进制包，请提供官方的二进制包下载地址。 |
| License检查    | 1、待适配软件是否有License。<br/>2、入库的License是否和官网对应版本的License保持一致。<br/>3、高风险license的开源软件谨慎选用，在适配前请充分评估并在申请时附上分析结论。 |
